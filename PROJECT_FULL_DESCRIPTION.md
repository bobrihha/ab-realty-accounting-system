# Полное описание проекта (пользовательское и техническое)

## 1. Что это за продукт (пользовательское описание)

**Система управленческого и финансового учета для агентства недвижимости** — веб‑приложение для ведения сделок, автоматического расчета комиссий, контроля денежных потоков, расчета зарплат и построения управленческой отчетности.

Продукт ориентирован на роли внутри агентства недвижимости: владелец, бухгалтер, РОП, агент, юрист. Система строит единый контур учета: сделки → прибыль → выплаты → казначейство → P&L.

### 1.1 Роли и доступ

- **OWNER (Владелец)**: полный доступ ко всем разделам, включая управление сотрудниками, ставками, юр. услугами, доступами.
- **ACCOUNTANT (Бухгалтер)**: финансы/P&L, казначейство, выплаты, команда, юридические услуги.
- **ROP (Руководитель отдела продаж)**: сделки своей команды, компенсации, финансы/казначейство, команда (без админ‑прав).
- **AGENT (Агент)**: свои сделки, личная зарплата (начисления/выплаты), KPI по своим сделкам.
- **LAWYER (Юрист)**: юридические услуги и отчеты по ним.

### 1.2 Дашборд и KPI

На главной странице (Dashboard) отображаются ключевые показатели:

- **Ожидаю итого** — сумма комиссии по всем активным сделкам (без отмененных).
- **В задатках** — сумма комиссии по сделкам в статусе `DEPOSIT`.
- **На оплате** — сумма комиссии по сделкам на финальных этапах (`REGISTRATION`, `WAITING_INVOICE`, `WAITING_PAYMENT`).
- **Ожидаемая прибыль** — сумма `netProfit` по активным сделкам.

Расширенная аналитика (с фильтрами по агенту и периоду):

- Выручка по дате брони.
- Выручка по дате сделки.
- Выручка в задатках.
- Выручка «в сделках» (ожидаю).
- Сделок на агента в месяц (среднемесячно).

### 1.3 Реестр сделок

Основной операционный раздел. Возможности:

- Полный CRUD сделок (создание, просмотр, редактирование, удаление).
- Фильтры: статус, агент, тип договора, застройщик, год/месяц сделки, год/месяц брони, юридические услуги, текстовый поиск.
- Воронка статусов:
  - `DEPOSIT` (Задаток)
  - `REGISTRATION` (На регистрации)
  - `WAITING_INVOICE` (Ждем счет)
  - `WAITING_PAYMENT` (На оплате)
  - `CLOSED` (Закрыта)
  - `CANCELLED` (Срыв)
- Типы договоров:
  - `EXCLUSIVE` (Эксклюзив)
  - `SELECTION` (Подбор)
  - `DEVELOPER` (Застройщик)
  - `SELLER` (Договор продавца)
- Финансовые параметры сделки:
  - цена объекта, валовая комиссия, налоговая ставка,
  - расходы по сделке (брокер/ипотека, юрист, рекомендация, прочее),
  - юридические услуги (флаг + сумма),
  - ставки агента и РОПа (можно вручную переопределить),
  - автоматический расчет комиссий и чистой прибыли.
- В карточке сделки показывается детализация расчетов и расходов.

### 1.4 Финансы / P&L

Отчетность по прибыли и убыткам. Возможности:

- Годовые и помесячные показатели (фильтры год/квартал/месяц).
- KPI по выручке/доходу/комиссиям/маржинальности.
- Разделение:
  - **Показатели** (автоматические метрики по сделкам)
  - **P&L** (выручка, расходы из казначейства, прибыль, маржа)
- Декомпозиция расходов по категориям и группам (маркетинг, офис, ФОТ, другие).
- Отчеты по агентам и РОПам:
  - годовая выручка по броням и сделкам,
  - комиссии,
  - средняя ставка,
  - помесячная динамика по каждому сотруднику.
- Экспорт в Excel (несколько листов: Показатели, P&L, Агенты, РОПы, Юр. услуги).

### 1.5 Казначейство

Контроль денег и прогноз кассовых разрывов.

- Справочник счетов: банковские, наличные, электронные.
- Учет операций **План/Факт**:
  - категории приходов и расходов,
  - плановые даты и фактические даты,
  - привязка к счетам.
- Балансы счетов автоматически корректируются при факте оплаты.
- Прогноз кассовых разрывов (на 12 месяцев) с индикацией:
  - Opening balance,
  - Expected income (ожидаемые приходы),
  - Planned expenses (плановые расходы),
  - Actual expenses (факт расходов),
  - Closing balance (итоговый баланс).
- Детализация расходов по месяцам (план/факт) с быстрым переводом плановой статьи в факт.
- Отдельный блок «Структура расходов» по категориям и периодам.

### 1.6 Команда

Справочник сотрудников + история ставок комиссий.

- CRUD сотрудников (только владелец).
- Параметры:
  - ФИО, email (логин), телефон,
  - роль, статус (активен/уволен),
  - отдел, РОП‑руководитель,
  - даты найма/увольнения,
  - базовые ставки агента/РОПа.
- История ставок комиссий с датой вступления (используется для расчета сделок).
- Статистика текучести:
  - всего агентов, активные/уволенные,
  - приняты/уволены за период,
  - динамика по неделям/месяцам/годам.

### 1.7 Выплаты

Ведомость начислений и выплат по агентам и РОПам.

- Таб «Начислено» — начисления по сделкам за период.
- Таб «Выплачено» — фактические выплаты по дате оплаты.
- Таб «К выплате» — полный накопленный долг по всем периодам.
- История выплат с фильтрами и поиском.
- Возможность создавать **частичные выплаты**.
- Автоматическое создание расходной операции в казначействе.
- Генерация текстового РКО (расходный кассовый ордер) для каждой выплаты.

### 1.8 Моя зарплата (для агента/РОПа)

Личный кабинет начислений:

- KPI по брони/сделкам/ожидаемым сделкам.
- Фильтры по периоду (год/квартал/месяц).
- Разделы «Начислено», «Выплачено», «К выплате».

### 1.9 Юридические услуги

Учет дохода от юр. услуг:

- Отдельные услуги (не привязанные к сделкам) — CRUD (владелец).
- Услуги из сделок (учитываются автоматически, если в сделке отмечен флаг).
- Показатели по месяцам:
  - количество услуг из сделок,
  - количество отдельных услуг,
  - суммы по каждому виду,
  - общая сумма,
  - зарплата юриста как % от суммы (настраивается).

### 1.10 Доступы

Хранилище логинов/паролей (OWNER‑only):

- категории, URL, логин, пароль, описание,
- поиск и фильтры,
- копирование логинов/паролей,
- скрытие/раскрытие паролей.

## 2. Техническое описание

### 2.1 Технологический стек

- **Frontend**: Next.js 16 (App Router), React 19, TypeScript.
- **UI**: Tailwind CSS, shadcn/ui, Radix UI, lucide-react.
- **Backend**: Next.js API Routes (Route Handlers).
- **ORM**: Prisma.
- **Database**: PostgreSQL (по умолчанию), поддержка инициализации SQLite через скрипты.
- **Auth**: NextAuth (Credentials Provider + JWT).
- **Dev tools**: ESLint, tsx, Prisma миграции.

### 2.2 Архитектура приложения

- **App Router** в `src/app`:
  - `page.tsx` — единый dashboard с вкладками.
  - `auth/signin/page.tsx` — страница входа.
- **API**: REST‑эндпоинты в `src/app/api/**/route.ts`.
- **Авторизация**: `next-auth` + `middleware.ts` (защита всех страниц, кроме `/auth/signin`, `/api/health`, статических ресурсов).
- **Данные**: Prisma Client в `src/lib/db.ts`.

### 2.3 Модель данных (Prisma)

Ключевые таблицы:

- **Employee** — сотрудники (роль, статус, ставки, руководитель).
- **CommissionRate** — история ставок комиссий (AGENT/ROP + effectiveDate).
- **Deal** — сделки (статус, даты, комиссии, расходы, результаты).
- **CashFlow** — операции казначейства (план/факт, категория, счет).
- **Account** — счета (банк/наличные/электронные).
- **CashFlowForecast** — прогноз кассовых разрывов (агрегированно по месяцам).
- **PayrollAccrual** — начисления по сделкам (агент/РОП).
- **PayrollPayment** — выплаты по начислениям (привязка к счету и CashFlow).
- **LegalService** — отдельные юр. услуги.
- **Credential** — реестр доступов.

Основные перечисления (enum): роли, статусы, статусы сделок, типы договоров, типы платежей.

### 2.4 Бизнес‑логика расчетов

#### 2.4.1 Комиссионный waterfall

В `src/lib/commissions.ts` рассчитывается каскад:

- `taxes = grossCommission * taxRate%`
- `cleanedBase = grossCommission - referralExpense`
- `ropCommission = cleanedBase * ropRate%`
- `agentCommission = cleanedBase * agentRate%`
- `netProfit = grossCommission - taxes - referralExpense - ropCommission - agentCommission - brokerExpense - lawyerExpense - otherExpense`

#### 2.4.2 Ставки комиссий

- Ставки агента/РОПа выбираются из `CommissionRate` по дате задатка.
- Если ставки не найдены — берутся базовые ставки из профиля сотрудника.
- В сделке можно явно задать ставку (override).

#### 2.4.3 Начисления и выплаты

- Начисления формируются автоматически при наличии `dealDate` и не отмененной сделке.
- При отмене или отсутствии `dealDate` начисления удаляются.
- Выплаты создаются как:
  - запись в `PayrollPayment`,
  - расходная операция в `CashFlow`,
  - уменьшение баланса счета.

#### 2.4.4 Финансы и P&L

- Выручка = сумма комиссий по закрытым сделкам за период.
- Доход = сумма `netProfit` по закрытым сделкам за период.
- Расходы = операции `CashFlow` со статусом `PAID` (кроме выплат агентам/РОПам).
- Прибыль = Доход − Расходы.
- Маржа = (Прибыль / Выручка) * 100.

#### 2.4.5 Метрики и аналитика

Метрики (API `/api/finance/metrics`):

- Выручка по броням (depositDate)
- Выручка по сделкам (dealDate)
- Стоимость объектов
- NetProfit
- Комиссии агентов/РОПов
- Средние ставки (% от базы)
- Помесячная динамика по агентам/РОПам
- Юр. услуги (по сделкам)

#### 2.4.6 Прогноз кассовых разрывов

Логика в `src/app/api/treasury/route.ts`:

- Opening balance = сумма балансов счетов.
- Expected income:
  - для прогноза — `netProfit` всех активных сделок (в первый месяц),
  - плюс **плановые** приходные операции `CashFlow` (PLANNED).
- Planned expenses:
  - плановые расходы `CashFlow` + повторяющиеся расходы,
  - исключая выплаты агентам/РОПам.
- Closing balance = Opening + Expected income − Planned expenses.

Исторический режим (для прошлого года) строится по факту закрытых сделок.

### 2.5 API эндпоинты (ключевые)

- **Auth**: `POST/GET /api/auth/[...nextauth]`
- **Dashboard**: `GET /api/dashboard`, `GET /api/dashboard/extended`
- **Deals**: `GET/POST /api/deals`, `GET/PUT/DELETE /api/deals/[id]`
- **Комиссии**: `GET /api/commissions/calculate`
- **Сотрудники**: `GET/POST /api/employees`, `PUT/DELETE /api/employees/[id]`
- **История ставок**: `GET/POST /api/commission-rates`
- **Финансы**: `GET /api/finance`, `GET /api/finance/metrics`
- **Казначейство**: `GET/POST /api/treasury`, `GET /api/treasury/kpi`, `GET /api/treasury/expenses`
- **Счета**: `PUT/DELETE /api/accounts/[id]`
- **Операции**: `PUT/DELETE /api/cash-flow/[id]`
- **Начисления/выплаты**: `GET /api/payroll`, `POST /api/payroll/payments`
- **Агентская статистика**: `GET /api/agent/stats`
- **Юр. услуги**: `GET/POST /api/legal-services`, `PUT/DELETE /api/legal-services/[id]`, `GET /api/legal-services/stats`
- **Доступы**: `GET/POST /api/credentials`, `PUT/DELETE /api/credentials/[id]`
- **Health check**: `GET /api/health`

### 2.6 Безопасность

- Все страницы защищены `middleware.ts` (кроме `/auth/signin`, `/api/health`).
- Аутентификация через `CredentialsProvider` (email + пароль, хеш в `Employee.passwordHash`).
- Роли хранятся в JWT и пробрасываются в сессию.

### 2.7 Структура проекта (основные папки)

- `src/app` — App Router страницы и API.
- `src/components` — UI и бизнес‑компоненты модулей.
- `src/lib` — общая бизнес‑логика (комиссии, зарплата, guards).
- `prisma/schema.prisma` — схема БД.
- `scripts/` — инструменты миграции, сиды, резервное копирование.
- `nginx/`, `docker-compose.yml`, `Dockerfile` — продакшн‑деплой.

### 2.8 Скрипты и обслуживание

- `npm run db:push` / `db:migrate` — миграции.
- `npm run db:seed` — создание OWNER пользователя:
  - email: `owner@agency.local`
  - password: `owner12345`
- `scripts/backup-db.sh`, `restore-db.sh` — бэкапы/восстановление.
- `scripts/migrate-to-postgres.sh` — миграция на PostgreSQL.

### 2.9 Деплой

- Docker compose: `postgres`, `app`, `nginx`.
- В `Dockerfile` используется multi-stage build, Prisma generate, standalone сборка Next.js.
- Healthcheck `/api/health` для мониторинга.

### 2.10 Переменные окружения

- `DATABASE_URL` — строка подключения к PostgreSQL.
- `NEXTAUTH_SECRET` — секрет для JWT.
- `NEXTAUTH_URL` — базовый URL приложения.
- `POSTGRES_*` — параметры БД в `docker-compose`.

## 3. Резюме

- контроле сделок и комиссий,
- прозрачности прибыли,
- управлении денежным потоком,
- автоматизации начислений и выплат,
- роли‑ориентированном доступе.
